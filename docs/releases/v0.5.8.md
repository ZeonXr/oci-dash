## 变更

- 容器默认以 root 运行，解决 Linux 自动创建的数据目录无法写入、启动时报 `unable to open database file` 的问题。
- 简化 Dockerfile 和 Compose，移除固定普通用户、构建期属主设置及额外容器权限配置。首次部署可直接运行 `docker compose up -d --wait`，无需预先设置 UID/GID 或执行 `chown`。
- 备份工具以 root 只读访问数据源，兼容旧 `1000:1000` 与新 root 所有的文件，继续保留原文件权限、隐藏密钥及服务运行状态。

## 升级

升级前备份完整数据目录，保留现有端口、数据挂载和可选覆盖配置。

- 使用本版本配套的 `compose.yaml`。沿用旧文件时，移除旧固定 `user`、`cap_drop: [ALL]` 和默认 `security_opt` 配置，避免旧限制影响新镜像读取已有数据。
- 现有数据目录直接继续使用，无需转换属主、迁移数据库或重新生成 `.master-key`。新建 Linux 数据文件通常由 root 所有，宿主机手工归档或恢复时使用相应权限。
- 默认端口仍为 `6240`，数据仍挂载为 `./data:/data`。单容器、Tini、35 秒停止期限和日志轮转继续保留。
- 回退到旧版普通用户镜像时，应使用匹配的升级前备份；旧镜像不能直接读取新创建的 root 所有且权限为 `0600` 的文件。

本版本提供 `linux/amd64`、`linux/arm64` 镜像及独立的 `compose.yaml` 附件。
